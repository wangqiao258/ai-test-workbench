> 状态：已评审通过并进入实施（2026-10-23，更新于 2026-10-26）。平台、runner、执行观测、
> 回归差异与 UI 执行能力已经落地；P3/P4 中未明确实现的部分仍按规划处理。
> 本文保留最初的分期方案和文件级清单，用于解释设计来源；阶段编号不代表当前全部能力状态，

## 1. 背景与目标

把工作台从"本机记录工具"升级为"服务器上的记录 + 执行平台"，支撑三个场景：

1. **批量探索与测试执行**：服务器连续执行数十/数百组测试，采集截图与结果，AI 事后统一分析差异，不需要人逐步盯。
2. **自动回归**：已验证用例保存成回归集，每次发布或新任务时重跑，与上次对比找回归异常。
3. **测试经验闭环**：缺陷连同场景、复现步骤、修复后验证结果一起沉淀；AI 下次分析同模块时优先用历史经验。

以儿童成长测评系统建第一批测试集（儿童档案、历史测评、报告边界条件、销售侧边栏展示），之后换项目复用引擎、只换业务规则（业务规则全是数据，见 §6.3）。

## 2. 角色分工（2026-10-23 与用户定案）

| 角色 | 职责 | 不做什么 |
|---|---|---|
| **AI（本地 WorkBuddy）** | 分析师：出方案（用例/断言/掩码，全是数据）、随时发起 run、读结果下结论、提 Bug | 不亲手执行、不写执行代码 |
| **应用（本平台）** | 账本（唯一事实源：契约/用例/结果/Bug/证据）+ 手脚（runner 执行/采集/回填） | 不做测试决策 |
| **服务器（CentOS Stream 9）** | 承载：算力/存储/网络 | 零决策 |
| **用户（人）** | 唯一质量门：审 Bug；拍板方向；提供授权与凭据（账号、小程序抓包 token） | 不做执行，不逐条审用例 |

关键变化：AI 从"又动脑又动手"变回"只动脑"，执行下沉 runner——解决"每一步都要人盯"。

## 4. 总体架构

```
本地 AI ──CLI(X-API-Token)──▶ 服务器:8501
                                 ├─ platform 容器（Flask+waitress，SQLite volume ./data）
                                 └─ runner 容器（P1+，只走 platform API，不摸库）
                                        └──▶ 被测系统（<被测域名>，内网直连）
```

> **实测约束（2026-10-23，地址已脱敏）**：服务器 `<平台地址>` 能解析 `<被测域名>`，
> 但**连不上 443（ConnectTimeout）**，出公网受限。runner 容器可构建、可启动，
> 直接跑会被 blocked（run 6 实测：21 条里 2 blocked / 19 skipped）。
> **结论：执行位置由"谁能访问被测系统"决定**，不强制放服务器。两种落地方式：
> 1) runner 跑在能出网的那台机器（开发机）；
> 2) 放服务器但给内网通路——`extra_hosts` 把域名指到内网 IP（见 `deploy/docker-compose.yml`
>    的 `UI_HOST` / `UI_HOST_IP`），或由网络组开白名单/代理。
> 这是网络问题，不是代码问题。

数据流闭环：AI 写"测什么"（用例/断言/掩码）→ 发起 run → runner 执行并回填（execution/packet/截图）→ 平台算 diff（P2）→ AI 读报告下结论（Bug/测试报告）→ 用户审 Bug。

### 6.1 新表 runs

```sql
CREATE TABLE runs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    project_id INTEGER NOT NULL REFERENCES projects(id),
    name TEXT NOT NULL DEFAULT '',        -- 人读，如 "接口回归-会员侧 第3轮"
    scope TEXT NOT NULL DEFAULT '',       -- JSON: {"batch":"接口回归-会员侧"} | {"module":["a","b"]} | {"case_ids":[1,2]}
    trigger TEXT NOT NULL DEFAULT 'ai',   -- ai / manual
    reason TEXT NOT NULL DEFAULT '',      -- 为什么跑（发布后回归 / 补缺口…）
    status TEXT NOT NULL DEFAULT 'queued',-- queued / running / done / failed
    baseline_run_id INTEGER,              -- 对比基准；缺省=同 scope 上一次 done 的 run
    summary TEXT NOT NULL DEFAULT '',     -- JSON: {total,pass,fail,blocked,skipped}
    created_by TEXT NOT NULL DEFAULT '',
    created_at TEXT NOT NULL,
    started_at TEXT NOT NULL DEFAULT '',
    finished_at TEXT NOT NULL DEFAULT ''
);
-- executions 增量加列：run_id INTEGER（可空，历史数据不动）
```

### 6.2 runs API

| 端点 | 说明 |
|---|---|
| `POST /api/runs` | AI 创建 run（project_id + scope + reason）→ 201 queued |
| `GET /api/runs?project_id=&status=` | 列表（网页端 P2 加"运行"页签展示） |
| `GET /api/runs/<id>` | 详情 + 关联 executions |
| `POST /api/runs/<id>/claim` | runner 原子认领（`UPDATE ... WHERE status='queued'`，0 行 → 409） |
| `POST /api/runs/<id>/finish` | runner 收尾：算 summary 落库，status→done/failed |

### 6.3 steps_json 扩展：机读断言 checks（引擎零硬编码的落点）

现状证据：137 条用例中 85 条带 steps_json（全 kind=api），但 `expect` 是自然语言，runner 无法判定。扩展每步加 `checks` 数组（向后兼容，旧数据无 checks 不受影响）：

```json
{"kind":"api","steps":[
  {"no":1,"action":"错误密码登录","request":{"method":"POST","path":"/admin-api/system/auth/login","body":{"username":"...","password":"wrong"}},
   "expect":"code != 0 且不返回 accessToken",
   "checks":[{"src":"status","op":"eq","value":200},
             {"src":"body","path":"$.code","op":"ne","value":0},
             {"src":"body","path":"$.data.accessToken","op":"absent"}]}]}
```

- `src`：`status` / `body` / `headers` / `duration_ms`（性能断言）
- `op`：`eq / ne / contains / not_contains / present / absent / gt / lt / regex / in`
- `path`：简化 jsonpath `$.a.b[0]`，`core/asserts.py` 纯函数自实现（不引第三方库）
- 判定：全过 → 步 pass；任一不过 → fail（记录失败断言）；请求异常/超时 → blocked
- **无 checks 的用例 runner 跳过**，run summary 里列 `skipped`——不拿自然语言猜，语义干净
- checks 由 AI 生成用例时一并产出（AI=分析师，产出数据）；`core/steps.py` 校验 checks 词表

**存量回填（P1 必做）**：回归批次 26 条**全是文本步骤**（2026-10-23 查库：batch 非空 26 条，steps_json 0 条）。P1 里由 AI 逐批补 steps_json + checks（`PUT /api/cases/<id>` 已支持），先补回归集，探索集按用逐步补。

### 6.4 runner 本体

- 位置：`runner/` 顶级包（与 api/ core/ 平级），只依赖 `requests`；**只消费公开 API，不 import api/core/db**——依赖方向 `app|api → core → db` 不变，runner 是 API 的普通客户端
- 配置全走 env：`PLATFORM_URL` / `API_TOKEN`（runner 专用 token）/ 轮询间隔（默认 5s）
- 执行循环：轮询 `GET /api/runs?status=queued` → claim → `GET /api/cases?...&fields=full`（full 含 steps_json，已核实 api/common.py:20）→ 逐条逐步执行 → 每步 `POST /api/packets`（全量报文，平台永不截断）→ 每条 `POST /api/cases/<id>/executions`（step_results + run_id）→ finish
- 单 run 内串行执行（配合 SQLite 单写者；并发是以后的事）
- 被测系统鉴权策略存 `project_settings`（§7.2）：侧边栏 = accounts 账号 + `POST /admin-api/system/auth/login {clientType:h5}` 换 token；家长端 = accounts 里存抓包 token，过期时相关用例标 blocked（actual_result 写明"token 疑似过期，需重抓"），不误报 fail

## 7. P2 回归对比

### 7.1 对比报告

`GET /api/runs/<id>/report`：与 baseline 对比，输出 `{new_fail, fixed, still_fail, new_cases, removed, resp_diff[]}`。resp_diff 用掩码后规范化 JSON 对比（`core/compare.py` 纯函数：掩码字段替换占位符、key 排序后深比）。

### 7.2 项目级配置表 project_settings（新表）

```sql
CREATE TABLE project_settings (
    project_id INTEGER NOT NULL REFERENCES projects(id),
    key TEXT NOT NULL,                    -- diff_mask / auth / ...
    value TEXT NOT NULL DEFAULT '',       -- JSON
    updated_by TEXT NOT NULL DEFAULT '',
    updated_at TEXT NOT NULL,
    UNIQUE(project_id, key)
);
```

- `diff_mask`：`{"paths":["$.data.timestamp","$.data.accessToken",...]}`。**AI 分析首批 run 的 packets 后提议，用户可在网页设置页审改**（设置页加配置区块）
- `auth`：runner 登录策略（§6.4）

## 8. P3 经验闭环

- **检索端点**：`GET /api/experience?project_id=&module=` → 一次返回该模块：历史 Bug（含驳回理由）、关联用例 summary、最近执行结果、接口 verify_status。AI 生成用例前先调它（替代现在 coverage + bugs 两三次手工拼）
- **修复验证**：Bug 详情页加"关联用例执行时间线"（读 `executions WHERE case_id=bug.case_id` 倒序），复跑后新结果自动出现；不新增任何 Bug 状态字段（§3-7）

## 9. P4 UI runner（边界锁死）

- 范围：**只做销售侧边栏 H5**（uni-app SPA，hash 路由）。登录 = accounts 账号走浏览器登录页（clientType=h5 免验证码，平台文档 #1 实测），storage_state 持久化到 `data/runner/`
- 镜像：runner 服务换 `mcr.microsoft.com/playwright/python` 基础镜像（Docker 化的核心理由之一）
- steps_json `kind=ui` 步骤格式**已定稿**：动作只有 `goto / click / fill / wait / eval`，
  断言统一走每步的 `checks`（`url/title/text/element`），字段与定位规则见
  `ai_guide_reference.md`「UI 用例」；`assert_text / screenshot` 这类动作不再保留
  （截图只在失败时由 runner 自动留证）
- **家长端不做 UI**（§3-9）

## 10. 安全模型更新与风险记录

| 取舍 | 风险 | 前提/缓解 | 退出条件 |
|---|---|---|---|
| 内网纯 HTTP（§3-4） | token、accounts 口令明文过网线 | 仅限内网可信网段；服务器防火墙只放行需要的来源 | 要出内网/有域名 → 立即加 Caddy 自动 HTTPS |
| 容器 root（§3-3） | 容器逃逸面 | 单机单服务内网工具 | 暴露面扩大 → 改非 root + chown data |
| 上传白名单+50MB（§3-5） | 原 /api/upload 无限制 | 词表 + 大小双闸门 | — |
| runner token 分权（§3-11） | runner 被仿冒 | 独立 token 可单独吊销；审计按 actor 区分 | — |
| 小程序抓包 token | 过期导致误报 | 过期标 blocked 不标 fail；提示重抓 | 找到可持续换 token 的途径 |
