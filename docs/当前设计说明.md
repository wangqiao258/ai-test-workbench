# 当前功能设计说明

> 本文只记录当前仍然有效的规则，合并自原来的模块分组、模块多选、用例锚点和 Bug 状态四份设计记录。
> 历史改造过程、当时的数据库统计和已经修复的问题不再保留。
>
> 相关文档：
> - AI 操作手册：`ai_guide.md`（运行时唯一规则来源）
> - 部署与执行引擎：`部署与执行引擎设计.md`
> - 执行观测边界：`执行任务管理与观测边界.md`
> - 数据包证据：`数据包证据.md`

## 1. 模块分组

### 1.1 唯一来源

- 模块的唯一来源是接口的 `interfaces.module`。
- `modules` 表是项目级受控词表，只负责保存模块名和排序，不单独维护层级关系。
- 用例有主接口时，`cases.module` 由该接口派生，不接受手填。

### 1.2 分组规则

分组是模块名的派生视图，不新增 `parent` 字段或独立层级表：

- 只认第一个 `-`；`侧边栏-客户` 的组名是 `侧边栏`，`A-B-C` 也归到 `A`。
- 没有 `-` 的模块（如 `系统`、`认证`）不是分组，仍作为普通模块。
- `侧边栏-`、`-客户` 这类残缺名称不产生分组。
- 带分隔符就归组，`min_size=1`；需要隐藏单成员分组时可以传 `min_size=2`。
- 分组按模块数量从多到少排序，数量相同按名称排序。

### 1.3 查询与交互

- 接口页、用例页支持 `?group=侧边栏`；`/api/interfaces`、`/api/cases`、`/api/coverage` 支持同一参数。
- 单个分组匹配 `module = 组名 OR module LIKE '组名-%'`。组名里的 `_` 按普通字符处理，不能越界匹配。
- 接口页和用例页可以同时携带 `group` 与 `module`，两者按交集收窄；`/api/coverage` 的范围参数互斥，`module` 优先于 `group`。
- 词表外的值按“没传”处理，不返回空白页。
- 选择分组后，模块候选收窄到该组；切换分组时先清空已选模块，避免形成必然为空的组合。
- 模块下拉按分组用 `<optgroup>` 归类，无分组的模块排最后；分组和模块都显示实际条数。
- 详情页返回链接通过 `back` 白名单保留 `group`，翻页链接也保留分组。
- Bug 页面是 560px 左栏的紧凑队列视图，不提供分组筛选。

## 2. 模块多选与 API 多值

### 2.1 URL 和 API 契约

- 多选统一使用重复键：`?module=A&module=B`，语义是并集。
- 网页筛选和 `/api/*` 使用同一套参数，URL 可以直接交给 AI 复用。
- 单值调用保持兼容：`?module=A` 仍等价于 `module = A`。
- 空值忽略；词表外的模块被丢弃；同名参数重复只计一次。
- `/api/interfaces`、`/api/cases`、`/api/coverage` 都支持多模块。
- `/api/coverage` 的响应同时保留单值兼容字段 `module` 和新的 `modules`；新代码使用 `modules`。

### 2.2 网页交互

- 模块面板使用原生 `<details>` + 同名 checkbox，不依赖隐藏域；浏览器直接提交重复键。
- 勾选模块时不自动提交，点击“应用”才刷新页面，避免面板在勾选过程中关闭。
- 面板底部实时显示“N 个模块 · M 条接口”，让使用者知道后续读取范围。
- 已选模块跨组时（只能通过手改 URL 产生），面板退回全量展示，避免提交时静默丢掉跨组模块。
- 点列表里的模块名只覆盖 `module`，保留分组、方法、关键字、环境等筛选，并回到第 1 页。
- Bug 页保持模块单选：固定左栏和队列式操作没有空间再放多选面板。

### 2.3 上下文纪律

- 先用 `/api/coverage` 多选或整组读取覆盖矩阵；它只返回标题、维度和缺口，适合一次看全貌。
- 接口契约按模块分批读取，不要一次把多个组块的完整契约全部放入上下文。
- 用例正文只在需要执行或修改时单条读取；列表默认使用 `fields=summary`。

## 3. 用例锚点、粒度与去重

### 3.1 锚点模型

用例必须至少有一个有效锚点：

| 用例类型 | 主锚点 | 说明 |
|---|---|---|
| 接口类 | `interface_id` | 决定模块归属，也是执行和覆盖统计的主要依据 |
| 页面/流程类 | `doc_id` | 指向 `dtype=page/flow` 的文档 |
| 跨切面/安全类 | `module` | 没有单一接口或文档可挂时使用，模块必须来自受控词表 |

- `interface_id` 是主锚点，`interface_ids` 是这条用例覆盖的全部接口；主锚点必须包含在关联列表中。
- 跨切面的分页、CORS、畸形 JSON 等用例可以同时关联多个接口，覆盖矩阵会在每个关联接口下计入。
- `module` 不是层级路径；目录树只用于浏览和 OpenAPI，不作为用例锚点或生成粒度。
- 批次信息放 `batch`，不要混进模块名。
- 持续生成用例还要关联 `target_id`、`generation_batch_id` 并填写 `novelty`，具体规则见 `ai_guide.md`。

### 3.2 粒度与覆盖维度

- 一条用例只验证一个清晰的风险或业务结论，不用一条“大用例”覆盖多个互不相关的检查点。
- 多接口用例用于同一风险跨多个接口成立的场景，不用于把多个独立测试意图硬拼在一起。
- 覆盖维度是受控词表：`正常`、`边界`、`异常`、`鉴权`、`越权`、`幂等`、`并发`、`兼容`、`性能`、`安全`。
- `dims` 是粗粒度索引，不代表该维度下所有风险都已覆盖；持续生成以测试目标池为准。

### 3.3 服务端查重

新增用例时会生成“测试行为指纹”，修改后会重新计算；它包含：

- 接口锚点和文档锚点；
- 前置条件；
- API 请求或 UI 操作；
- 关键输入和断言；
- 没有机读断言时的文本预期。

新增时先比较行为指纹，再比较归一化标题。重复返回 `409`，并带 `duplicate_kind`、`duplicate_of`、`existing_title` 和 `existing_anchor`。修改用例后，旧执行结果不再证明新版本已覆盖测试目标。

- 换标题但行为相同仍会被拦截。
- 不同输入、不同前置状态或不同断言属于不同测试意图。
- `force=true` 只用于确认两者确实是不同风险的情况，不能用来绕过持续生成查重。
- 目标用例被判定重复时，应先给测试目标回写 `duplicate` 反馈。

### 3.4 结构化步骤

- `steps_json` 可选，但接口类和要自动执行的用例强烈建议使用。
- 结构包含 `kind=api|ui|mixed` 和步骤数组；每步必须有 `action`、`expect`，以及且只能有 `request` / `ui` 之一。
- `request.path` 只写路径，域名统一由环境决定；一条用例最多 50 步。
- 提供 `steps_json` 后，平台自动渲染人读的 `steps` 文本，只维护一份数据。
- 每一步都有 `checks` 才能交给 runner 自动执行；任何一步缺 `checks`，整条用例进入 skipped，不能算通过。
- 执行结果优先按步回填 `step_results`，总结果由步骤推导；显式结果与推导结果矛盾时返回 400。

## 4. Bug 分诊与上报

### 4.1 一条轴，四个状态

Bug 不再维护“开发修没修”的 `status` 轴。平台只负责分诊和上报，开发修复在公司在线表格中跟进。

| `review_status` | `reported_at` | 含义 | 是否在默认视图 |
|---|---|---|---|
| `pending` | 空 | 待审核 | 是 |
| `approved` | 空 | 待上报（已通过，还没抄表） | 是 |
| `approved` | 有值 | 已上报（已抄进公司表格） | 否 |
| `rejected` | 空 | 已驳回 | 否 |

默认视图是“未结案”（`core/lists.bug_todo_where`，全站唯一实现）：

```text
review_status = 'pending'
   OR (review_status = 'approved' AND COALESCE(reported_at,'') = '')
```

### 4.2 筛选与计数

Bug 页的“进度”筛选取值：

| 筛选 | 含义 |
|---|---|
| `todo` | 未结案，默认值 |
| `pending` | 待审核 |
| `toreport` | 已通过但未上报 |
| `reported` | 已上报 |
| `rejected` | 已驳回 |
| `all` | 全部 |

- 项目页 Bug 数量表示项目内全部记录数。
- 导航栏“Bug 审核”表示未结案数，即待审核 + 待上报。
- `/review` 收件箱与导航角标同口径（同一段 SQL）：待审核 + 待上报。两者口径分叉过一次，
  待上报的那条把角标撑成 1，点进去却是空页，只能挨个项目点 Bug tab 去找。
- Bug 页的状态筛选保存在 URL 中，`progress` 等筛选键加入 `back` 白名单。

### 4.3 操作规则

- 待审核：通过 / 驳回。
- 待上报：标记已上报 / 改判驳回。
- 已上报：撤销上报 / 改判驳回。
- 已驳回：改判通过。
- 驳回必须填写原因，并使用结构化 `reject_category` 分类，便于统计 AI 提报质量和复盘。
- 通过和驳回可以互改；改判为通过时保留原驳回意见，避免一次误操作抹掉历史。
- 批量通过只对“还没通过”的记录生效（待审核、已驳回），已通过的待上报记录一律跳过，
  否则批量操作会把当时的审核意见清空。
- 驳回会清空 `reported_at`，避免出现“已驳回却已上报”。
- 只有 `approved` 的记录可以标记上报；上报时间使用 `reported_at` 这个事实字段，不再增加第四个枚举值。
- AI 修改 Bug 的任何字段或追加证据后，Bug 重新进入 `pending`，重新经过人工质量门。
- Bug 提交前使用标题查重和 `/api/bugs` 的质量规则；只有 Bug 需要人工审核，文档、接口、用例仍提交即生效。

## 5. 通用交互约定

- 筛选状态以 URL 为唯一来源，刷新、分享和浏览器前进后退都能恢复。
- 从详情页返回使用 `back` 参数，只接受白名单键，禁止开放重定向。
- 列表页只加载索引字段，正文、步骤和证据在详情页或面板按需加载。
- 词表外参数一律按没传处理，不制造难以解释的空白页。
- 切换 tab 会清空跨 tab 无意义的筛选参数。
- 新增功能改变上述规则时，同步更新本文和 `ai_guide.md`；历史过程放进 `backups/`，不要继续在 `docs/` 堆叠另一份“新旧混合”的设计记录。

## 6. 覆盖缺口与 UI 覆盖

覆盖有两条轴，不能互相替代：

- **接口覆盖** = 有用例的接口 ÷ 总接口（主锚点或 `case_interfaces` 关联都算）；
- **UI 覆盖** = 有 UI 用例的模块 ÷ 有接口的模块。

`dims` 只描述风险维度，**不参与 UI 覆盖判定**：给一个模块补满 10 个维度，UI 覆盖仍然是 0。
UI 用例只认 `steps_json` 里真的有 `ui` 步骤（`kind=ui|mixed` 都算），不看 dims，也不能用
`steps_json LIKE '%"ui"%'` 判定（请求体里出现 `"ui"` 键会误判）。

口径只有一份实现（`core/coverage.py`），三个出口共用，不允许各算一套：

| 出口 | 用途 |
|---|---|
| `GET /api/coverage` 的 `totals.interface_coverage` / `ui` / `gaps` | AI 冷启动找缺口；默认只给模块级汇总，`?ui=full` 才展开页面明细 |
| 首页质量面板的两个徽标 | 人一眼看到覆盖红线：接口覆盖健康线 80%、UI 覆盖 30% |
| `POST /api/test-targets/from-gaps` | 按缺口批量登记目标：零用例模块优先，其次零 UI 用例模块 |

派活是幂等的：同一缺口按 `target_fingerprint` 去重，已登记过返回 `skipped + duplicate_of`。
`POST /api/test-targets/next` 在没有 open 目标时返回 `gap_hints`，避免 AI 空转或自由发挥。

含 UI 用例的 run 创建时返回 `ui_cases` 与 `warnings`（提示 runner 容器在跑、页面地址可达），
只提示、不拦创建——平台探测不到 runner 机器能力，手工回填的路径不能被堵死。

## 7. 相关验证

- `tests/verify_module_groups.py`：模块分组派生、下拉联动和上下文保持。
- `tests/verify_multi_select.py`：重复键多选、分页保留和覆盖矩阵。
- `tests/verify_filters.py`：列表筛选、分页与返回链接。
- `tests/verify_bug_views.py`、`tests/verify_bug_review.py`：Bug 分诊、审核和上报。
- `tests/smoke_api.py`：用例锚点、字段裁剪、查重和 API 兼容（含手册必须保留 UI/缺口入口的断言）。
- `tests/verify_generation.py`：持续生成目标、行为查重和执行反馈闭环。
- `tests/verify_coverage_gaps.py`：两条覆盖轴的口径、gaps 与模块行一致、UI 覆盖不认 dims、`from-gaps` 幂等与 `next` 的 gap_hints。
- `tests/verify_pages.py`：页面路由与参数组合、详情页 404 边界、未登录跳转。
- `tests/verify_ui_contract.py`：模板内联 JS 与渲染 DOM 的契约（悬空 id、表单 action、注入 JSON 字段）。
- `tests/verify_api_gaps.py`：Token 鉴权矩阵与未覆盖端点的读写边界。
